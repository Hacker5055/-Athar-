### حزم مقترحة لحساب المواقيت والقبلة
- **المواقيت:** `adhan_dart` — نسخة Dart محمولة من مكتبة Adhan JS المختبرة، تدعم طرق حساب متعددة، المذهب، قواعد خطوط العرض، والتعديل اليدوي، بدون اعتماديات خارجية [1](https://pub.dev/packages/adhan_dart) [5](https://pub.dev/packages/adhan_dart/example). (يوجد كذلك حزمة `adhan` [3](https://pub.dev/documentation/adhan/latest/)).
- **البوصلة:** `flutter_compass` [1](https://pub.dev/packages/flutter_compass)، أو `flutter_device_compass` كنسخة مُصانة حديثًا [6](https://pub.dev/packages/flutter_device_compass)، أو القراءة الخام من `sensors_plus` [5](https://pub.dev/packages/sensors_plus) مع حساب رياضي نقي لتعويض الميل والميل المغناطيسي [8](https://github.com/AbdeldjalilChougui/qibla_math).

> **نقطة تقنية حرجة للقبلة:** البوصلة بتقرأ **الشمال المغناطيسي**، واتجاه القبلة محسوب على **الشمال الحقيقي**. لازم تطرح/تضيف **الميل المغناطيسي (declination)** حسب الموقع والتاريخ قبل مقارنة الزاويتين، وإلا الخطأ في أوروبا وأمريكا يوصل لعشرات الدرجات.

## 2. بنية المشروع (Feature-first Clean Architecture)

```
lib/
├── main.dart
├── app/
│   ├── app.dart                 # MaterialApp.router + theme + localization
│   ├── router.dart              # go_router + ShellRoute للتبويبات
│   └── bootstrap.dart
├── core/
│   ├── theme/                   # tokens, light/dark/quran themes
│   ├── l10n/                    # ar, en, fr
│   ├── db/                      # drift database + migrations
│   ├── error/                   # failures + result type
│   ├── utils/                   # date, hijri, numbers, formatters
│   └── widgets/                 # مكوّنات مشتركة (AtharButton, AtharCard...)
└── features/
    ├── onboarding/
    ├── home/
    ├── prayer/
    │   ├── data/                # datasources (calc, prefs), repositories impl
    │   ├── domain/              # entities, repositories (abstract), usecases
    │   └── presentation/        # screens, widgets, providers
    ├── quran/
    ├── adhkar/
    ├── qibla/
    ├── tasbih/
    ├── tracker/                 # «أثري»
    ├── calendar/
    └── settings/
```

**قاعدة:** كل feature مستقلة؛ الـ `domain` لا يعرف Flutter ولا Drift. التبعيات تتدفق `presentation → domain ← data`.

## 3. مصادر البيانات **والترخيص** (أهم قسم في الملف) ⚖️

### 3.0 القرار المحسوم ✅

> ## أثر **تطبيق مجاني للأبد**
> بلا إعلانات · بلا اشتراك · بلا «ادفع لتفتح ميزة» · بلا بيع بيانات.
> التمويل الوحيد: **تبرّع اختياري** («ادعم أثر»).
>
> **تاريخ القرار:** ٢٠٢٦-١٠-١٨ · القرار ملزم لكل الأسابيع اللي جاية.

**ليه القرار ده مهم تقنيًا (مش بس تجاريًا):**
بيشيل أكبر قيد كان واقف قدامنا. مصادر كتير مرخّصة «للاستخدام غير التجاري فقط»
بقت **متاحة لنا بالكامل**. وكمان بيخلّي شاشة «المصادر والتراخيص» حاجة ثقة مش التزام قانوني بس.

**لكن قيدان يظلّان قائمَين مهما كان القرار:**

1. **إعادة التوزيع ≠ الاستخدام.** أغلب التراخيص تسمح بعرض المحتوى *جوه* التطبيق،
   لكن تمنع تقديمه كـ **حزمة بيانات / API / تنزيل للغير**. إحنا «أوفلاين أولًا»
   فبنخزّن المحتوى جوه التطبيق — وده **استخدام مشروع** (مش إعادة توزيع)،
   لكنه **تخزين دائم**، وده بالظبط ما يقيّده Quran Foundation صراحةً (راجع ٣.١).
2. **الإسناد ليس كماليات.** كل مصدر محتوى لازم يظهر في شاشة «المصادر والتراخيص».
   تطبيق مجاني سمعته هي رأسماله الوحيد.

### 3.2 الترجمات والتفسير

- الترجمات الإنجليزية العامة (Yusuf Ali, Pickthall, Sahih International) غالبًا متاحة،
  لكن **بعض ترجمات Tanzil مسجّلة كمقيّدة** [3](https://github.com/risan/quran-json) — نتحقّق من كل إصدار على حدة.
- **الفرنسية (Hamidullah):** ⚠️ يحتاج تحقّقًا صريحًا من حالة الترخيص قبل التضمين (أولوية عالية لأن FR لغة أساسية).
- **التفسير:** نبدأ بتفاسير حالة حقوقها واضحة (مثل المختصرات المتاحة للنشر)،
  ونؤجّل ما التبس ترخيصه.
- **القاعدة:** لكل ترجمة/تفسير نحتفظ بملف `provenance.json` داخله:
  الاسم، المؤلف، المصدر، الرابط، الترخيص، تاريخ الإضافة، وهل يسمح بالتخزين الدائم.
  وشاشة «المصادر والتراخيص» تعرضهم بشفافية.

### 3.4 الأذكار

- **حصن المسلم** (سعيد القحطاني) — مرجع أساسي؛ راجع شروط النشر قبل التضمين الكامل.
- إن تعذّر الإذن: نبني المجموعات من **أمهات كتب الأحاديث الصحيحة** مباشرةً
  (البخاري · مسلم · أبي داود · الترمذي · النسائي · ابن ماجه) مع **تخريج كامل**.
- **قاعدة غير قابلة للتفاوض:** كل ذكر لازم يكون عليه **تخريج** (الكتاب/الحديث/الرقم) أو يُترك.

---

### 3.5 المواقيت والقبلة

- **لا نحتاج مصدر بيانات نهائيًا** — كلها حسابات فلكية رياضية محلية.
- التاريخ الهجري: خوارزمية (أم القرى أو الجدولي) + **إزاحة يدوية ±1/±2 يوم**
  (لأن الهلال بالرؤية، والخوارزميات تختلف).

### 3.6 شاشة «المصادر والتراخيص» (ميزة ثقة)

بما أن التطبيق مجاني للأبد، **الشفافية هي عملتنا**. الشاشة تعرض لكل مصدر:
الاسم · type (نص/ترجمة/تفسير/صوت/خط) · الترخيص · الرابط · تاريخ الإضافة.
تُبنى تلقائيًا من ملفات `provenance.json` — لا تُكتب يدويًا أبدًا.

---

> ### 🟢 القاعدة الذهبية (بعد قرار «مجاني للأبد»)
> 1. **لا نجمع من مصدر يمنع التخزين الدائم** إلا للتحقّق.
> 2. **لا نحزم صوتًا** إلا بترخيص نسخ وإعادة نشر صريح.
> 3. **لا نعرض ذكرًا بلا تخريج.**
> 4. **كل مصدر يُسجَّل في `provenance.json` ويظهر للمستخدم.**
> 5. لو تغيّر القرار التجاري يومًا ما → **إعادة مراجعة هذا القسم بالكامل قبل أي سطر كود محتوى.**

## 6. البحث (Search)

- **FTS5** في SQLite على: نص الآية (بدون تشكيل + بدون همزات + توحيد الألف/الياء)، الترجمة، اسم السورة.
- **تطبيع النص العربي** قبل الفهرسة: إزالة التشكيل، توحيد (أ/إ/آ→ا، ى→ي، ة→ه)، إزالة التطويل.
- بحث صوتي (fuzzy) للتعامل مع أخطاء الكتابة.
- بحث بالرقم: `2:255` و`البقرة 255` و`الصفحة 42` و`الجزء 3`.
